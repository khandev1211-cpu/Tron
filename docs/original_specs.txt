1. Architectural Overview & Core Objective
The purpose of this project is to construct a lightweight, high-performance, automated operational dashboard to track, isolate, and log transactional activity among TRC-20 USDT accounts 👉.
To achieve maximum cost efficiency, the system explicitly splits network operations from computational resource loops:
•	The Brain (VPS Tier): Ingestion, data storage checks, filtering logic, and communication loops operate 24/7 on a low-power cloud server for a low, flat monthly rate.
•	The Muscle (GPU Tier): Heavy cryptographic verification and pattern matching calculations are completely offloaded to a pay-as-you-go infrastructure array that runs only on-demand, by the second.




2. Functional Module Breakdown & Requirements
Module A: The Directory Harvester & Trait Pre-Generator
This batch processing engine automatically parses the live blockchain state, registers target assets, and structures the layout matrix 👉.
•	Identification Parameters: Connects to the network ledger interface via the primary API gateway to scan addresses containing a current balance profile \(\ge \) 7,499.00 USDT.
•	Currency Precision Requirements: All asset values must be evaluated using arbitrary-precision math types (decimal.Decimal) rather than standard binary floats to prevent rounding discrepancies across the 6-decimal sub-units of the USDT token contract.
•	Trait Extraction Layer: Slices the first 4 characters following the initial identifier prefix and the last 5 trailing characters of every matching address string, generating a unified reference frame model.
•	Exclusion Guardrails: Automatically drops any wallet profile whose 4x5 target sections contain noncanonical or ambiguous Base58Check layout characters (0, O, I, l). This step is critical to protect downstream hardware from infinite execution processing loops.
•	Storage Specifications: Profiles are injected using a non-transactional pipeline wrapper directly into a local loopback in-memory database (Redis). Values are stored under a separate tracking namespace with a volatile 24-hour expiration window (TTL) to keep memory structures clean.


Module B: The Real-Time gRPC Network Stream Listener
This background module acts as a continuous interceptor for live transaction events occurring across the network ecosystem.

•	Connection Protocols: Opens a persistent, low-latency gRPC network stream to raw TRON block nodes, shifting processing away from traditional, throttled HTTP JSON polling methods.
•	Filter Logic Layers: Filters all streaming smart contract event signatures to capture only the specific log hashes of the official USDT contract address (TR7NHqjeKQxGTCi8q8ZY4pL8otSzgjLj6t).
•	Velocity Tracking Boundaries: Scans live Transfer amounts on local system threads, flagging a transaction immediately if the balance volume falls exactly within the 1 to 501 USDT threshold window.
•	Validation Cross-Reference: The millisecond a transfer matches the size threshold, the listener cross-references the sender address against the active Redis database in local RAM. Lookup execution must process in under 1 millisecond.
Module C: The Two-Way Interactive Alert Interface
This messaging pipeline packages verified events and presents them cleanly to the remote operational dashboard on your phone.
•	Outbound Interface Notification: Packages matching events into an unthrottled HTTP POST notification message dispatched immediately to a secure Telegram Bot API group endpoint.
•	Notification Layout: Messages are structured using Markdown layouts to prominently display the transfer size, origin address, target wallet balance metrics, and a direct verification explorer link.
•	Actionable Frame Array: Appends an inline keyboard matrix configuration button directly beneath the notification block payload, labeled with a dynamic marker command (e.g., "🛠️ Vanity It!").
Module D: The Automated FIFO Task Queue & Action Engine
This structural backend layer intercepts screen actions and routes execution steps directly into physical hardware commands.
•	Inbound Core Listener: Runs a persistent background loop on your monitor server using secure long-polling queries to handle tap tracking.
•	Security Lockdowns: Restricts all incoming command executions to a single hardcoded numerical user identity variable, dropping all unauthorized requests instantly.
•	FIFO Queue Management: Employs a strict First-In, First-Out (FIFO) queue worker shell script to hold multiple incoming click confirmations, protecting graphics infrastructure from thread collision crashes.
•	GPU Lookahead Parallelization: Pulls the trait rule from the queue context and executes a highly optimized, case-insensitive C++/CUDA vanity address generator matrix (tron-profanity-latest). This maps the task across thousands of thread blocks concurrently on an NVIDIA RTX 4090 system layer, discovering a structural address match using complex regular expression constraints within 2 to 12 seconds.
